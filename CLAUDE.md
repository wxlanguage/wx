# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

WX is a Rust-implemented compiler for a language that targets WebAssembly. Syntax is Rust-inspired. This is a bachelor's thesis project.

## Current state (branch `tir-refactor`)

The type checker has been rewritten and the pipeline runs end to end again: `wx check` and `wx build` compile a program to Wasm. Not everything the checker accepts is lowered yet.

- **Live:** `ast`, `vfs`, `diagnostics`, `tir` (checking, `tir::check`, which returns the live `Semantics`; and lowering it to MIR, `tir::lower`, in `tir/lower.rs` + `tir/lower/`), `mir` (the arena IR and the inliner), `opt`, `codegen`, `wasm` and `backend`. The embedded stdlib sweeps with zero diagnostics. `wx-cli` builds and its `check`/`build`/`format` work; `wx lsp` prints that the server is not connected to the new checker yet and exits.
- **Kept on disk as reference, not compiled:** `tir/builder/` (the old body checker, ~22k lines, to port from), `tir/tests.rs` and `tir/snapshots/` (the old TIR suite), the commented-out old data model in `tir/mod.rs`, and in `mir/` the pre-rewrite lowering (`legacy_lowering.rs`, `builder/`, `types.rs`, `mono.rs`, `static_data.rs`, `tests.rs`); `codegen/tests.rs` is disconnected too.
- **Not compiling:** `wx-lsp` and `wx-compiler-wasm` still reference the removed `TIR`/`MIR::build` API. This is expected mid-refactor state; don't "fix" it as a side effect of unrelated work.
- **Function bodies, basic version:** `BodyBuilder` (`typecheck.rs`, with `typecheck/{blocks,calls,members,patterns,places}.rs`) builds a body from syntax, and `BodyContext` (a body in its scope; `typecheck/decide.rs`, `typecheck/exhaustiveness.rs`) holds what is valid on it whatever wrote it and decides what building left open; together they check constant and global initializers and function blocks: blocks and scopes, locals, `if`, `loop`/labels/`break`/`continue`/`return`, direct function calls with inferred type arguments, paths through a type to a function (`Ordering::of(..)`, `Self::f`, `T::f`, `<T>::f`, `<T as Tr>::f`, with member privacy; a generic type named without its arguments, `Layout::of::<T>()`, leaves them to the call to learn and proves the impl's bounds afterwards), method calls (`x.m::<T>(..)`, no auto-deref; a `self: M::*Self` method is called on the pointer itself), a positional list that fills one parameter as that parameter's whole value (`g(a, b)` is `g((a, b))` for `g(p: (A, B))`; `x.m(a, b)`, but `T::m(x, (a, b))`; one value for several parameters is their tuple, `f(p)`, `Point(p)`, `x.m(p)`; nothing is regrouped, so `T::m(x, p)` is a wrong count), calls by name (`f({ b, a: 1 })`, `x.m({ .. })`, `T::m({ self: x, .. })`; the names are the trait declaration's for a trait impl's function, and a function with an unnamed parameter is positional only), `Self(..)` construction inside an impl for a struct, associated constants (`P::SIZE`, `T::SIZE`, `Self::PAGE_SIZE`), places (`.*`, field access, `.&`, `x[i]`; each step goes through at most one pointer: `p.field` is `p.*.field` for a pointer `p`, a pointer to a pointer has no fields, and indexing follows the same rule: `x[i]` (`PlaceKind::Element`) indexes a place of slice or array type where it is (`h.data[i]`, `s.*[i]`, `m[i][j]`), and goes through a pointer to one once (`s[i]` is `s.*[i]`), so `x.*[i]` for a pointer to a pointer to one; its index is the memory's `Size`), the assignment family, patterns (`local` destructuring and `match`, in one pattern arena, `body::PatKind`), with exhaustiveness and unreachable arms from one usefulness pass (`tir/usefulness.rs`). String and array literals (`[a, b]`, `[v; n]`, `[v; _]`) are arrays, data in no memory (`"hi"` is `[u8; 2]`, `[1, 2]` is `[{integer}; 2]`), which wait for their context as an untyped literal does (`TypeInterner::needs_context`) and are placed in a memory when coerced to a shared pointer (`coerce_static`), then evaluated into allocations by `eval.rs`; a constant may hold one (`const G: [u8; 5] = "hello"`), and each use places a copy (`place_constant`, `place_data`). Functions are values of their own zero-sized item type (`local g = id::<u8>;`, or `local g: id<u8> = id;`); a call of a value (a local, a constant, a computed callee) goes by its type: `func(A) -> R` implements `Call` by a compiler rule and is a `CallRef` (lowering to `call_ref`), any other type is a call of `Call::call` with the value as `self` (`v(a, b)` is `v.call((a, b))`); an item's arguments are its function's, by position or name, packed into `Args` as a call's `args` are, and any other type's are by position. A type without the trait an operator or a call needs is E2063 (`TraitBoundViolation`), reported like any unmet bound ("the trait bound `V: Add` is not satisfied", with the operator marked "required by `+`"). Slice range syntax is not supported. Const parameters and constant arguments parse but are reported as `UnsupportedExpression` (E2114, bug severity); the stdlib raises none. Plan: `notes/tir-body-checking-plan.md`.
- **Trait-impl conformance** (`tir/conformance.rs`, one `CheckConformance` obligation per written trait impl): members missing (E2033), of the wrong kind (E2079) or not in the trait (E2078); each function's signature against its declaration read with `Self` as the target (own type parameter count, parameter count, parameter names, types; E2080; an impl names a parameter as the trait does or leaves it unnamed, which binds no local and keeps the contract) and each constant's type (E2081), compared by substituting and normalizing both sides and comparing the interned results, with a walk over the two types (and their written syntax) only on a mismatch, to point at the innermost written part that differs; supertraits proved for the target; associated type values against their declared bounds; an impl function's own type parameters may require no more than the declaration's (E2124, rustc's E0276): the function is read in a check-only assumption env (`contract_env`, rustc's hybrid `ParamEnv`) parented on the impl's, holding the declaration's own clauses instantiated with `Self` as the target and the function's own parameters as the declaration's, where its own clauses are proved and its signature is compared. A concrete call still sees the impl's own (possibly weaker) bounds.
- **Lowering** (`tir/lower.rs`): reads the live `Semantics` and builds MIR, monomorphizing per `FunctionInstance` on a worklist. Its module doc lists what is lowered; every other checked form is reported as `UnsupportedExpression` (E2114), never dropped. Inlining, then `opt` and `codegen` per function, run in `backend::emit`.
- **Inherent impl locality** (`tir/impls.rs`): an inherent impl must be in the package defining its target (E2077, `ForeignImplTarget`); imports and package aliases do not change ownership. Builtin constructors belong to std. Other modules/files in the defining package are allowed, and trait impls may target foreign types.
- **Receiver types** (`tir/obligations.rs`): a method's first `self` parameter must be its enclosing `Self` or exactly one pointer to it (E2053, `InvalidSelfType`). Signature construction records the check; declaration checking compares normalized types, including aliases, associated types, and the method's own `Self` refinements. Receiver position is checked separately in `decls.rs`.

Design and rationale: `notes/tir-type-context.md`, `notes/tir-to-mir-transition-spec.md`. Every package in `examples/` checks and builds in the current syntax, except `arena`, an unfinished design experiment kept as is; CI does not build them.

## Commands

```bash
# Build
cargo build -p wx-compiler       # core library
cargo build --release -p wx-cli  # CLI binary → target/release/wx

# Run the compiler on a project (every subcommand takes a *directory*
# containing a wx.json, never a bare .wx file)
wx build .                       # → <dir-name>.wasm; `-o -` writes to stdout
wx check .                       # type-check only, no output emitted
wx format .                      # in-place; --check for a diff-free exit code,
                                 # --files a.wx,b.wx to restrict the set
wx lsp                           # language server over stdio (disconnected for now)

# `build`/`check` accept --message-format human|short|json

# Inspect WASM output (WABT is installed)
wasm2wat output.wasm             # disassemble to WAT text format
wasm-objdump -d output.wasm      # annotated disassembly

# Test — most tests live in wx-compiler, but wx-fmt and wx-lsp have their own
cargo test --workspace
cargo test -p wx-compiler -- <test_name>  # single test by name

# Update snapshots when output changes legitimately
cargo test -p wx-compiler
cargo insta accept

# Lint (this exact form is what CI gates on)
cargo clippy --workspace --no-deps -- -D warnings

# Format Rust sources
cargo fmt
```

Current baseline (2026-11-11, debug): 1452 `wx-compiler` (plus 2 ignored, the `<<` parser bug in `ast/tests.rs`) and 75 `wx-fmt` tests pass (a few need `debug_assertions`, so release runs fewer); `wx-lsp` and `wx-compiler-wasm` do not compile, so `--workspace` commands fail on them (CI's `cargo check --workspace` is red for that reason). ## Crates & binaries

`wx` is a single native binary (from `wx-cli`) with `build`/`check`/`format` (alias `fmt`)/`lsp` subcommands — there is no separate `wx-lsp` binary anymore. `wx-lsp` is a library-only crate (no `main.rs`): it exposes `build_service()` (builds the `tower-lsp-server` `LspService`) and `run_stdio(stdin, stdout)` (serves it over a caller-supplied transport). `wx-cli`'s `lsp` subcommand (`cmd_lsp` in `wx-cli/src/main.rs`) used to spin up a current-thread Tokio runtime for the server, the only async part of the CLI; while `wx-lsp` is disconnected it only prints an error and exits, and `wx-cli` does not depend on `wx-lsp`.

`run_stdio` is `#[cfg(not(target_arch = "wasm32"))]`: `tower_lsp_server::Server`'s `AsyncRead`/`AsyncWrite` bounds resolve to a different trait depending on which of its features is active (`tokio::io`'s under `runtime-tokio`, native; `futures::io`'s under `runtime-agnostic`, wasm32), so it can only compile for the target whose trait it's bounded by. `wx-lsp-wasm` (excluded from the main workspace — wasm32-only) only ever calls `build_service()` directly and bridges the transport over `postMessage` instead.

The two wasm crates (`wx-compiler-wasm`, `wx-lsp-wasm`) are built with `wasm-pack` **run from inside the crate directory** — `wx-lsp-wasm/.cargo/config.toml` pins `target = "wasm32-unknown-unknown"`, and Cargo's config discovery only picks that up when invoked from within that directory. Each produces a `pkg/` that `web-next/package.json` consumes as a `file:` dependency. There is no committed task or npm script wrapping this, and `pkg/` is not checked in.

Two web frontends are tracked: `web/` (the deployed playground — `.github/workflows/deploy.yml` builds it with Deno and pushes to Deno Deploy; depends on the published `@wx-lang/wasm-bindings`) and `web-next/` (its in-progress Monaco/LSP-backed replacement, wired to the local `wasm-pack` output above).

Distribution: `wx` (all subcommands, including `lsp`) ships via GitHub Releases and npm (`@wx-lang/cli`, per-platform optional deps) — see `.github/workflows/publish-cli.yml`. Release binaries are stripped (`[profile.release] strip = true` in the root `Cargo.toml` — cheap enough, no build-time cost, to apply everywhere including a plain local `cargo install`); `lto`/`codegen-units = 1` are enabled only in `publish-cli.yml`'s build step via env vars, not in `Cargo.toml`, since they meaningfully slow down builds and should only cost time on binaries actually being shipped.

CI (`.github/workflows/ci.yml`) runs only `cargo check`/`test`/`clippy` over the workspace. It does **not** build or check anything under `examples/`, so a broken example will not fail CI.

`thesis/` is gitignored — the bachelor's thesis lives in its own repo ([MellKam/bachelor-thesis](https://github.com/MellKam/bachelor-thesis)) and is merely cloned into this working directory for convenience. Its `thesis/CLAUDE.md` belongs to that repo, not this one.

## Editor integrations

`editors/` holds one git submodule per supported editor, each a fully self-contained repo under the `wxlanguage` org (own `package.json`/lockfile, own `.github/workflows/`, own `.vscode/` debug config) — nothing about them lives in the main repo beyond the submodule pointer and `.gitmodules`. `editors/vscode` ([wxlanguage/vscode](https://github.com/wxlanguage/vscode)) is functional; it doesn't bundle a `wx` binary, it resolves `wx` from the user's `PATH` (or an explicit `wx.path` setting) and spawns `wx lsp`, the same model as `deno.path`. `editors/zed` ([wxlanguage/zed](https://github.com/wxlanguage/zed)) is an MVP: a self-referential tree-sitter grammar (`[grammars.wx]` in `extension.toml` points `repository`/`rev` at this same repo, with the grammar source under `grammar/` via the `path` field — a real but undocumented `GrammarManifestEntry.path` field, confirmed from Zed's source rather than its docs) that gives real structure to top-level items but parses signatures/bodies as generic balanced-token groups rather than a full expression grammar; verified against every `.wx` file in this repo with zero parse errors. `src/lib.rs` resolves `wx` the same way as the VS Code extension (`Worktree::which("wx")`), with Zed's native `lsp.wx.binary.path`/`arguments` settings as an override — no custom setting needed. Not yet published to Zed's extension registry; install as a dev extension for local testing. Zed's own extension registry (a submodule tree itself) requires each listed extension to live in its own repo, which is why this follows the same one-repo-per-editor structure as `vscode` rather than living directly under `editors/`. Clone with `git clone --recurse-submodules`, or run `git submodule update --init` after a plain clone — a submodule directory is empty until explicitly initialized. To debug an editor integration, open its `editors/<name>` folder directly as its own VS Code window rather than from the `wx` root, since its `.vscode/launch.json` only applies there.

**Neither extension registers file watchers.** The server declares its own at `initialized` over `client/registerCapability` (`**/*.wx`, `**/wx.json`) and receives `workspace/didChangeWatchedFiles`; `didSave` is not used. Doing it server-side is what lets Zed — whose extensions can only supply a server command, with no file-watching API of their own — see manifest and off-buffer source edits at all. Don't reintroduce a per-editor watcher.

## Project model — `wx.json`

Every compilation is rooted at a **package**, and every package needs a `wx.json` next to its sources. There is no anonymous single-file compilation path: `wx build`/`check`/`format` all take a directory, and `wx-lsp` finds a file's package by walking ancestors for a `wx.json` (a file with no such ancestor gets a rust-analyzer-style "unlinked file" hint rather than silent nothing).

```jsonc
{
  "type": "bin",             // "bin" | "lib" | "std"
  "entry": "main.wx",        // required, relative to this manifest — never guessed
  "dependencies": {
    "math": { "type": "local", "path": "../math" }
  },
  "format": {                // all optional; each falls back to RendererConfig::default
    "max_line_width": 80,
    "indent_width": 4
  }
}
```

Parsed by `vfs::manifest::PackageManifest`, resolved into `PackageGraph`s by `vfs::resolve::open_manifest`. Unknown top-level keys are ignored, so a manifest written for a newer wx still loads on an older one.

- **A package has no name of its own, and a `dependencies` key does not put one in scope.** The key only makes the package *available* to the declaring package (`Package.dependencies`, keyed by `PackageName`). Source names it with a package instance, `package "key" as alias;` (see "Language features"), so the same package can be instantiated under several aliases, in any module. The stdlib is registered first in every package's `dependencies` as `std` (it is not reserved, just claimed first), so a manifest key `std` is a duplicate name (E0002); a `"type": "std"` dependency is E0004.
- **`"type": "std"`** means *this package provides the stdlib itself* (it defines the items the language requires: primitives, operator traits, intrinsics, found by name), so the embedded stdlib is not also loaded. It is not a freestanding mode — wx has none. Only `crates/wx-compiler/std/wx.json` uses it.
- `DependencySource` is `#[serde(tag = "type")]` from the start, so a future remote/registry source is an additive variant rather than a breaking reshape. Only `local` exists today, and its `path` is a `RelativePath` — always relative to the declaring manifest, never the process cwd, enforced as a type invariant.
- Formatting config is read from the manifest in exactly one place, `RendererConfig::from_manifest` in `wx-fmt`. `wx format` and the LSP's formatting request are the same operation and must agree byte for byte — don't add a second overlay. (Note: a doc comment on `cmd_format`'s config helper still describes a `--manifest <path>` flag that does not exist in the clap definition.)

## Compilation pipeline

```
wx.json + source text
    │  vfs::resolve::open_manifest() → package graph
    │  ast::Parser::parse() per file
    ▼
AST  (src/ast/)
    │  vfs::CompilationUnitBuilder::new(&mut strings)
    │      — load_stdlib()/load_package()/load_binary()/build() → CompilationUnit
    │  tir::check(&compilation, &mut strings) → Semantics (owned; its diagnostics())
    │  tir::lower(&mut sema, &strings)         → Result<MIR, ()> (`wx build`)
    ▼
TIR  (src/tir/) — the live Semantics: signatures, checked bodies, values
    │  tir/lower.rs — monomorphizes per FunctionInstance and builds MIR
    ▼
MIR  (src/mir/) — monomorphic functions over Wasm-shaped values, arena bodies
    │  backend::emit(&mut mir, strings, inline policy)
    │      mir::inline::run — inlining and dead-function removal
    │      opt::optimize_reachable — per reached function: graph → uses,
    │          locations → placement → emit, replacing its MIR body
    │      codegen::Builder::build — linearize each body to wasm::Function, encode
    ▼
WASM bytecode (WasmModule::encode() → Vec<u8>)
```

`tir::lower` refuses a `Semantics` whose checking reported an error or a bug, and reports its own failures on it, so `sema.diagnostics()` holds checking's and lowering's diagnostics either way.

`CompilationUnit` owns diagnostic gathering for the whole package graph — `collect_parser_diagnostics()`, `collect_linker_diagnostics()`, and `collect_diagnostics()` (both, interleaved per package). Don't walk `packages`/`modules` by hand to print or count diagnostics; and use the `Diagnostics` extension trait (`errors`/`error_count`/`has_errors`) rather than spelling out `Severity::Error | Severity::Bug`, since dropping `Bug` from any one such check is a silent hole.

The stdlib is embedded at build time by `crates/wx-compiler/build.rs`, which walks `std/**/*.wx` into `STDLIB_FILES: &[(&str, &str)]` (`/`-prefixed path relative to `std/`, source). `StdlibFileSource` serves it to the loader by reading that table directly. Adding a stdlib file means creating it and writing the `mod` declaration that references it — there is no third list to update. `std/main.wx` (std is one file) declares the primitives as bodiless `pub type`s, the operator traits, `StackValue`, `Pointer`, `Slice`/`Array`, `Memory`, `Global`, `Call`, the intrinsics as `pub package func` items (package function parameters the compiler fulfils for std only, `Intrinsic::from_std_name`), `impl` blocks for the primitives, and stdlib constants.

- **`vfs/`** — `mod.rs` (`CompilationUnit`, `PackageGraph`, `Files`, file sources), `manifest.rs` (`wx.json` schema), `resolve.rs` (manifest → package graph), `path.rs` (`AbsolutePath`/`RelativePath`)

- **`diagnostics.rs`** — the single `define_diagnostic_codes!` macro and the `Code` trait, shared by every stage
- **`../std/main.wx`** — standard library source (sibling to `src/`), embedded via `build.rs`

## TIR (rewrite)

Import blocks accept explicit `use` items (named, aliased, grouped or glob),
including `pub use`, with the same visibility and private-re-export checks as
modules. A use entry is not a Wasm import declaration or export. There is no
implicit parent glob. Keep the existing recursive lookup and cycle checks: a
private `use super::*` in the block combined with `use host::*` in its parent is
rejected; named imports in at least one direction avoid that loop. No lookup
trail or new per-hop accessor-resolution semantics are used.

Known separate follow-up: glob lookup can expose a private named alias when
its underlying definition is visible to the accessor. Import-block `use`
support deliberately does not change that existing glob-visibility behaviour.

**Phase 1 — `Declarations::build`** (`decls.rs`, with `imports.rs`/`paths.rs`): seeds one root scope per package (`package`/`self` are real bindings, and `std` is bound in every package but the stdlib's own; other dependencies are bound by package instances as they are scanned), creates one scope per file, prescans every item into `ast_nodes: Vec<AstEntry>` (parse order) and per-kind arenas with stable indices (`FunctionIdx`, `StructIdx`, …), and resolves `use` imports and globs on demand. Output is read-only afterwards. `ImplDispatch::build` then indexes impl targets. Namespaces are addressed by their owner: a `Namespace` (`Package`/`Module`/`Enum`/`Import`) is what a path continues into, a `Scope` (`Package`/`Module`/`Import`) is where code is written (an unqualified lookup's start, a privacy check's accessor, every item's `namespace`). Their tables live in `decls.namespaces: Namespaces`, one list per owner kind indexed by the owner's own index. Only a scope has a parent, globs and `self`/`package`/`super`; an enum's table holds just its variants. Imported declarations and their synthetic impls use their block's own scope: sibling names resolve directly, enclosing names need `super::` or `package::`, exactly as in modules. There is no enclosing-scope fallback in path resolution.

**Name resolutions** (`resolutions.rs`): every written name the compiler resolves is recorded in one `NameResolutions` table, keyed by a `Site` (`Type(span)`, `Value(span)` or `Label(span)`: where the name is written and the role it plays there, ordered by position first) and mapping to a `Reference`. `Type` and `Value` are the namespace tiers a name is looked up in (`Site::new(tier, span)` builds one from a `Tier`); `Label` is a name that picks out a declaration by where it is written, a named argument's parameter or field (`ArgumentLabel`; a constructor field label means initialization) or a `break`/`continue` label (`Referent::Label`). A shorthand argument `f({ x })` is therefore two entries at one span, its label and the value it supplies. Ordinary names are `Reference::Name(Referent)` (`Declaration`, `Import { declaration, import }` for a name made visible by a named `use` or a glob, `TypeParam`, `Member`, `Label`); a local or a field selection carries an `AccessKind` (`Read`, `Write`, `ReadWrite`). The access belongs to the named node a use ends at, not to the names it is reached through: `value` in `s.inner.value = n` is written and `inner` is read; an index passes it to its object (`data` in `p.data[i] = n` is written), unless that object is a pointer, which `[i]` only reads (the one record `downgrade_to_read` overwrites; `build_operand` reports the site it recorded through its `site` out-parameter, passed up through indexes too, as in `p.data[i][j] = n`). The one exception is the root local of a value chain: `check_assignable`, which already walks to it to require `mut`, records it as written (`s` is `Write` in `s.inner.value = n`), so a local's `Write` means assigning needed `mut`; a chain through a pointer is a place and never gets there (`s` stays `Read` in `s.pointer.value = n`). So `build_operand` threads one `AccessKind` down and never walks an operand twice. Declarations (a local's, a label's, an item's name) are not entries: they live in their owning tables (`Body::locals`, `Body::labels`). The table is built next to the diagnostics, lent `&mut` to `Declarations::build` and `ImplDispatch::build`, and then owned by `Semantics`; `PathResolver` holds it with the other things a walk writes. Only code that has committed to a meaning records it (the walk records each segment it resolves; `resolve_type_path` records a parameter once it chose it over the namespace walk; member selection records the member it picked). There are no per-definition `accesses` lists: who refers to a definition, or which `use` items are unused, is the inverse of this table.

**Phase 2 — `Semantics` and `SemanticsBuilder`** (`signatures.rs`): `Semantics` is the single owner of semantic type state (interner, bounds, scope frames, per-kind signature tables, bodies, normalization state) and holds no syntax. It has no lifetime: it owns `decls`, `ImplDispatch`, the solver, the diagnostics and the name resolutions, and `tir::check` returns it. The string interner is the one input it does not own (one interner outlives many compilations): an operation that reads a name takes it explicitly as its first parameter (`sema.normalize(strings, env, ..)`), and the short-lived structs over `sema` hold it as a field (`BodyContext::strings`, `Lowerer::strings`, `SemanticsBuilder::strings`, which is `&mut`, since only building interns, a string literal's contents). `SemanticsBuilder<'ast>`, its sibling, turns syntax into that state: it borrows the prescan's AST entries, the source files and the interner, and holds the signature queries (`query_state`, `query_stack`) and each declaration's obligations, and lives only for the sweep. Its operations take the semantics as `sema` (`builder.ensure_signature(sema, query)`), and the solver, evaluation, obligation checking, `BodyContext` and lowering never reach it. `SemanticsBuilder::build(sema)` runs five phases: `ensure_signature(DeclId)` for every declaration; `build_constant_bodies` (every constant's and variant's initializer, value-free); `check_declarations`; `check_constant_bodies` (what each constant body left undecided, its evaluation and what it owns, an enum's discriminants); and `check_bodies` (function blocks and global initializers; a global's initializer is then evaluated at compile time by `evaluate_global` into `global_values`, and one that is not a constant expression is E2015). It then resolves the export block and debug-asserts everything is `Resolved`. Obligations are only requirements a signature recorded and could not decide during construction; what is written *inside* a declaration is a body, built by a per-body `BodyBuilder` and decided by a `BodyContext` (`typecheck.rs`); the solver's re-entry (`decide_obligations`) makes only a `BodyContext`. A body records what its own lowering requires (a written type, a construction's bounds) in its own list and checks it on the spot. Every constant body is built before anything evaluates, because the solver evaluates a constant by reading its body and builds none; so a constant's body is built *value-free*: it normalizes with `RewriteFlags` without `VALUES`, which leaves a `Const` as written, and records what needs a value beside the body as a `DeferredCheck` (an obligation that can reach a value, a type equality as rustc's `ConstEquate`, a literal's length, a match's usefulness), decided in `check_constant_bodies`. The trigger is syntactic (`has_const` after a rigid normalization), not a failed read. A function's or global's body normalizes with every fact and defers nothing: every value is known by then. Design: `notes/tir-constant-evaluation.md`. The context is **not frozen** afterwards: it stays live and mutable. Do not reintroduce a frozen `SignatureRegistry`, a stored interner reference, or `Arc`/`Rc`/`unsafe`. Owning its state is what lets the LSP keep it alive next to the `CompilationUnit` and the interner: `notes/type-context-ownership-refactor.md` (all of its steps are done).

A declaration's identity is `decls::DeclId`, the arena it lives in and its index there (`DeclId::Struct(StructIdx)`, …; an enum variant is a `Const`). The prescan assigns it; the parser assigns none, so the AST is plain syntax. A trait a typeset generates is built by the typeset's query (`TraitDecl::typeset`), and `Declarations::name` reads any declaration's written name. `ensure_signature` is demand-driven and re-entrant. `query_state: HashMap<DeclId, QueryEntry>` holds a `QueryState` (`Pending`, `InProgress`, `Resolved`, `CycleReported`); `query_stack` records in-progress frames in call order so a cycle diagnostic can name the whole loop. It returns `SignatureStatus { Available, CycleReported, Cycle }`, which is `#[must_use]`: handle `Cycle`, or write `let _ = …` with a reason. Once a frame is pushed, every path must reach the unwind that pops it; a leaked `InProgress` entry makes later cycles name items that finished long ago. Construction lowers written syntax and neither checks a bound nor normalizes: sites record an `Obligation` (bounds, trait membership, and well-formedness, which normalizes each written type once) in the list the lowering's caller passes (`obligations: &mut Vec<Obligation>`). `ensure_signature` owns one per query and keeps it with the declaration (`QueryEntry::obligations`); once every signature exists, `check_declarations` checks each declaration's obligations in place, in definition order. There is no global obligation list. A check never rewrites a stored signature; a failure is diagnosed and the type is kept as written, with projections unreduced. Unqualified `Type::Name` selection uses declared bounds, the `ImplDispatch` index and assumptions only; a member of a projection that those cannot find records `CheckProjectionMember`, and the declaration's check reports the ambiguity with the qualified spelling as the suggestion (E2104). Semantic queries (`normalize`, `find_trait_impl_query`, `satisfies_clauses`, `stack_value_repr`, `const_value`, …) read finished signatures, never force one, and never emit. They are methods of `Semantics` (`solver.rs`, `eval.rs`), not of `Solver`: `Solver` is a plain struct holding the engine's state (the derivation in flight `SolverState`, the normalization cache, the `Verdict`s, layouts, constant values, allocations, static values). `Semantics` owns it (`Semantics::solver`), and a query reaches it there so that it can re-enter body checking. There is no `SolverView`. The solver's one error type is `SolverError` (`Pending`, `Poisoned`, `Overflow`, `Cycle`); a query that cannot finish (budget or cycle) returns it, and the construct that owns the requirement reports it once (`overflow_diagnostic`/`cycle_diagnostic` in `obligations.rs`). Lowering failures still become `TypeIndex::ERROR` in place. Two kinds of `solver::Definition` are on the solver's own path and own their loops: an impl member's value for an associated type (`Definition::Member`: its own, or the trait default it inherits, keyed by `ImplMember { impl_index, declaration }`), and an impl's requirements, the bounds on its parameters (`Definition::Requirements(ImplKind)`), proved for its own parameters in its own scope. The solver judges each once on first use and memoizes a `Verdict` in `Solver::verdicts` (`Unchecked`/`InProgress`/`Resolved`, or `Poisoned`/`Overflowed`/`Cyclic` when it has no meaning); impl selection consults the impl's verdict before proving its requirements for the arguments at hand. A judgement is a frame on the solver's own stack (`SolverState::frames`, the counterpart of `query_stack`: `SolverFrame::Judgement` for a member, `SolverFrame::Requirements` for an impl), with a budget counted from where it started. Reaching a definition again while it is judged is a loop (for requirements: selecting the impl's own instantiation again; other arguments are ordinary recursion): through an equality written in a bound (`SolverFrame::Equality`) it is a tautology and stays abstract; through definitions only it is a cycle owned by its first-defined definition (an impl's requirements before its members), whose check reports it (`CheckAssocValue`; `CheckImplRequirements`, at the bound the loop closed in), and every other reader of a failed verdict fails silently. Other declarations' bounds are proved only where they are used, so they are not definitions here. So a loop through any number of values is one diagnostic regardless of source order, and checks need no ordering among themselves. A successful normalization is memoized when its answer read no open frame below its own request (`SolverState::lowest_frame_read`: a cycle, a re-entered judgement or a rollback each record the frame they read); only a request with no frame open reads that cache. A request for a type with no parameter is keyed and computed under the root scope (`Normalization::new`): only an abstract type (`TypeInterner::is_abstract`: a parameter, or a projection out of one) takes assumptions, so such a type means the same in every scope. A projection out of a concrete type (`<P as Container>::Item`) is not abstract: it reads its trait's declarations (`is_param_or_projection`) but never the scope's assumptions. Any path that reads a non-final fact must return `Pending`, which is what keeps the cache valid. Design and open points: `notes/tir-check-pass.md`.

Semantic queries (`find_trait_impl_query`, `normalize_*`, `resolve_type_member`, `resolve_trait_qualified_member`) are methods on `Semantics`; declaration-local assumptions are read through `ClauseTables` from an `assumption_context: AssumptionEnvIdx`. A declaration's parameters live in a generic env (`GenericEnvIdx`, identity: names, flat slots) and what it assumes in an assumption env (`bounds::AssumptionEnvArena`, parent-chained; an item that writes no bound shares its parent's, and `Normalization` is keyed by it). What a scope or an associated declaration assumes is a flat run of clauses about any subject (`bounds::BoundClauses`, one range into the `ClauseArena`, every kind a variant of `bounds::Clause`): `Clause::Trait` (`subject: Trait`, nested bounds as clauses on projections) and `Clause::Equality` (`projection == value`), with each trait's own clauses (its supertraits) copied in with `Self` substituted. A run is published in two stages: the memberships as `BoundClauses::Provisional` before any value is resolved, so a sibling's value can name members they supply, then the whole run, pushed again as one range, as `Final`. A reader of one kind filters (`ClauseArena::traits`/`equalities`); a new kind is a new variant. An associated declaration's clauses are not expanded into a parameter's; they are read along a receiver's projection path (`declarations_of`), since a recursive trait describes infinitely many paths. A binding in a bound (`Tr where { N = .. }`) names `Tr`'s own member, or else the one its supertraits declare (two different traits declaring it is E2059, as `T::N` is), and is kept under the declaring trait (`SourceAssocBinding::target`), so `GlobalMut where { Value = u32 }` states `<G as Global>::Value == u32`. A use proves the clauses with the use's arguments (`Solver::satisfies_clauses`): impl selection each env on the impl's assumption chain, a use each frame's own env (`BoundRequirements::Frame`), both whole (`Subjects::All`); an associated declaration's clauses are read over its value (`Subjects::Rooted`). A use's generic arguments (a written type's, a call's, a selected impl's) live in the `GenericArgArena` with the span each is given at (written, learned from a value, or the name), and a failure is reported at the argument its clause is rooted at; body nodes hold theirs there too (`GenericArgs`), since the interner's lists back interned types only. Ambiguity between equalities is decided where they are read; a conflict between values an outer constructor tells apart is reported once, when the clauses are built. `StackValue` (std) has no impls: the solver answers it from the receiver's structure (`TraitImplLookup::Builtin`). `Solver::stack_elements` walks a type's parts in declaration order, flattened, zero-sized ones dropped, into scalars (`i32`, `i64`, `f32`, `f64`, `funcref`) and abstract parts assumed `StackValue`; an abstract part not assumed one makes it no `StackValue`, and anything containing `!` is uninhabited, held as `!` (its `Repr`, which no other type's equals, so `transmute` never makes one and no global is one). `Semantics::stack_value_repr` routes value checks and membership through the ordinary normalization cache for `<T as StackValue>::Repr`; only successful answers are stored, and abstract answers require evidence of the bound. Failed queries locate an offending part separately, on the diagnostic path. `StackValue::Repr` is reduced by `Semantics::compute_stack_value_repr` with no new type variant: the flat tuple of scalars, or else the projection again over a canonical self type (the flat tuple of the elements), so `<Wrap<T> as StackValue>::Repr` is `T::Repr` and `Pair<T, u32>` and `(T, u32)` both give `<(T, i32) as StackValue>::Repr`; a pointer is its address, then its `Pointer::Metadata`, each count as wide as the address, and into an abstract memory that is `M::Size` (std's `PointerSize: StackValue` keeps that element a `StackValue`). Design: `notes/stack-value.md`. Trait-impl conformance is `conformance.rs`'s (see "Current state").

**Old body checker (`tir/builder/`, not compiled):** feature-sliced (`operators`, `calls`, `control`, `paths`, `traits`, …), each slice owning its `report_*` diagnostics; `type_compare.rs` did trait-conformance signature comparison. When porting a slice, move it onto `BodyBuilder` (or `BodyContext`, if deciding needs it) rather than recreating a second declaration-query system.

## Type system

Every type is a `TypeIndex` (u32) into `tir.types` (a `TypeInterner`). The first 20 slots are pre-interned by the hardcoded `[Type::Infer, Type::Error, ..., Type::Funcref]` list in **`TypeInterner::new()` (`tir/types.rs`)** — the reverse `index_lookup` is built by iterating over it — and MUST match the `TypeIndex` constants declared in the same file. Never insert into or reorder the list without renumbering the constants in the same edit; a new pre-interned type goes at the end. `BOOL` and `CHAR` are not compiler types: they hold std's `pub enum Bool(u8) { False = 0, True = 1 }` and `pub struct Char(value: u32)` as `Type::Enum`/`Type::Struct`, so interning either finds its slot. Prescan records them by name in the std package (`decls.intrinsics.bool`/`.char`), and `Semantics::new` passes them to `TypeInterner::new(bool, char)`; a std without them is a panic, not a diagnostic. Only syntax still knows them: conditions, `&&`/`||` and comparison results are `BOOL`, a char literal can become `CHAR`; everything else (layout, `StackValue`, impls, operators, exhaustiveness) treats them as the enum and struct they are, so `!`, `&`, `|`, `^` on a `Bool` and every `Char` operator are calls of std's impls, and constant evaluation holds a `Bool` as its `u8` and a `Char` as its `u32`.

Each interned type carries `TypeFlags` (`HAS_INFER`, `HAS_ERROR`, `HAS_LITERAL`, `HAS_PARAM`, `HAS_PROJECTION`, `HAS_CONST`, `HAS_UNPLACED`), computed once in `TypeInterner::insert` from its own kind and its parts' flags, as rustc does: `has_infer`/`has_error`/`has_literal`/`has_param`/`has_projection` answer "anywhere inside" without walking the type. `HAS_UNPLACED` (a slice or an array: literal data waiting for a memory) is the one flag that does not reach everywhere: only a tuple passes it on, and a pointer, a nominal type's arguments, a function type and a projection drop it, so `needs_context` is `has_literal || has_unplaced`. `substitute` returns a type without `HAS_PARAM` unchanged and `Solver::normalize` one without `HAS_PROJECTION`, so a flag must never be missing where its variant occurs. Only `TypeProjection` is a projection: a trait's function type (`<Point as Make>::make`, the declaration over `Self`) is nominal and never normalized into the impl's member; the impl is chosen where the call is resolved. A new compound `Type` variant must say in `flags_of` which parts it inherits from.

Type-level constants share the type space, as in GHC's DataKinds rather than rustc's separate `Const`: `Type::Value { bits: u64 }` is a constant inside a type, and `Type::Array { of, length }` (`[T; N]`, behind a `Type::Pointer` as `M::&[T; N]`) holds its length as a `TypeIndex` (a `Value`, a `Const`, or `INFER` for a written `_` until a literal fills it). `Type::Const { constant, type_args }` is a constant named in a type (`[u8; SIZE]`), the constant counterpart of `TypeProjection` (it carries `HAS_PROJECTION`): normalization replaces it with its `Value` when its facts include `RewriteFlags::VALUES` (the ones `ALL` has), and leaves it as written otherwise. `RewriteFlags` is a flag set (`EQUALITIES`, `DEFINITIONS`, `VALUES`) next to the depth in a request's cache key, and `Semantics::normalize(strings, env, ty, depth, facts)` is the one entry point (there are no per-use wrappers). Its `type_args` follow `Type::Function`'s layout (an impl's, then its own; `[Self]` for a trait's) so impl, trait and generic constants (`const N<S: PointerSize>: S = 0`, planned) fit the same variant; today only free constants are built, with no arguments. A constant length behind a pointer records `Obligation::CheckConstantType`: the constant's type must be exactly the pointer's memory's `Size`, or the constant an untyped count representable as it (no value relaxation for typed constants; generic constants are the planned answer for abstract memories). Evaluation is the solver's (`Solver::const_value`, in `eval.rs`): a memoized query whose evaluation is a frame (`SolverFrame::Evaluation`) on the solver's own stack, with a budget of its own, so a loop through constants is read from the same stack as one through projections, and normalizing a `Const` evaluates it in place. The solver reads bodies and builds none: every constant body exists before anything evaluates, and a constant's body never asks for a value (it is checked value-free), so evaluation never meets an unbuilt body. A constant's evaluation is a frame opened before its declared type is read, so `const A: heap::&[u8; A] = [0; _]` is a loop on the solver's stack (E2109). What a constant owns (a failure, a loop) is reported by `evaluate_constant` in `check_constant_bodies`, and the checks that met it are silent. A `Value` has no type of its own (rustc's `ty::Const` dropped its `ty` for the same reason): a length is a count, and behind a pointer it is held as `<memory as Memory>::Size`, so `M::&[u8; 4]` matches `heap::&[u8; 4]` structurally. Lowering a pointer to an array with a written length records `Obligation::CheckConstantRepresentable` (`length_representable`), which checks the value against that type once signatures exist: a concrete integer's range (E2004), or, for an abstract memory, every member of the typesets its `Size` is bounded by (`PointerSize`, so `u32` and `u64`; E2047), so a generic type works with every memory. There is no `kind()`: kinds are checked by syntax where an argument meets its parameter, and are correct by construction after that. A constant with parameters (a trait's, an impl's with arguments) is evaluated per instance (`eval::Instance`, the constant with its arguments, memoized in `Solver::instance_values`): its body is checked once and evaluated with the arguments substituted, a trait's declaration reads the member of the impl its `Self` selects or the default the impl inherits (`resolve_constant`, which also answers `Array::LEN` from the type), and an instance's failure is reported by its first reader. A length may name a type's constant (`[u8; T::SIZE]`, `Self::K`, `A::LEN`, `<T as Array>::LEN`, `<[u8; 4]>::LEN`): it lowers to `Type::Const` with the impl's arguments, or the trait's declaration over the type as `Self` (as `T::Item` is a projection, with a `CheckTraitMembership`), and normalizing it with `VALUES` resolves and evaluates it once `Self` is known; over an abstract `Self` it stays rigid, so `[u8; T::LEN]` equals itself. Const parameters are the next step.

`INTEGER_LITERAL`, `FLOAT_LITERAL` and `CHAR_LITERAL` are literals' pseudo-types (`Type::*Literal`, `HAS_LITERAL`): a literal keeps one until its context gives it a type, and `coerce` rewrites it in place; with no context it is E2002 (a type annotation is required), never a default. A character literal becomes `Char`, or any integer type that can represent its code point (`'0': u8` is 48, `'€'` is representable as `u16` but not as `u8`), never a float; a character literal with an integer one is a character literal (`'a' + 1`), as an integer with a float is a float. A char literal pattern compares by code point against a `Char` or an integer scrutinee. A string literal is the array of its bytes (`[u8; 5]`), not a pseudo-type: placed, it becomes a shared byte slice (`heap::&[u8]`) or a shared byte array of exactly its length (`heap::&[u8; 5]`), in whatever memory the context names, abstract ones included.

`INFER` (slot 0) is a type inference placeholder — used internally when a generic type argument cannot yet be determined, and will be the type of user-written `_` in type annotations. Must never reach MIR or codegen.

`UNIT` (slot 2) is the empty tuple, `Type::Tuple { elements: [] }`, not a variant of its own, so interning an empty tuple anywhere returns it. There is no tuple of one, as in ML: `(T)` and `(T,)` mean `T` in types, expressions and patterns. The AST has no grouping node: any parenthesized list, `(x)` and `(x,)` included, is a `Tuple` recorded as written (elements `Separated`, so a trailing comma is kept); the meaning is TIR's: interning a tuple of one returns its element (as an empty one returns `UNIT`), and a one-element tuple expression, place or pattern is checked as its element. wx-fmt prints a one-element tuple type or pattern as its element, and an expression one as the grouping `(x)`, since its parentheses may group it (`(a + b,) * c`); a pattern of alternatives keeps its parentheses. `NEVER` (slot 3) is written `!` (`TypeExpression::Never`), as in Rust; it is not a std item.

There are no `true`/`false` keywords: `True` and `False` are `Bool`'s variants, which std re-exports (`pub use Bool::*;`). A bare name in a pattern binds, so a pattern compares with them as `const True` or `Bool::True` (the form exhaustiveness witnesses are rendered in).

## Language features (current state from tests)

- Primitives: `i32`, `i64`, `u32`, `u64`, `f32`, `f64`, `u8`, `i8`, `u16`, `i16`, and `funcref` (a Wasm `funcref`, a function reference of any signature; it has no memory layout and nothing uses it yet beyond naming the representation of `func(A) -> R`). They are **real items**: bodiless `pub type X;` declarations in `std/main.wx`, recognized by name in the std package and bound to the matching pre-interned `TypeIndex`, so they carry `DeclId`s and resolve like any other name.
- A slice `[T]` and an array `[T; N]` are types in no memory (`Type::Slice { of }`, `Type::Array { of, length }`; a length is an integer literal, a constant path (from a bracketed root too, `<T as Array>::LEN`), or `_`, never a computation, and `const` before it is redundant, W1003). Only a pointer holds one, `M::&[T]` (fat: address and length) or `M::*[T; N]` (thin), and the AST mirrors it (`&[T]` is a `Pointer` to a `Slice`). A value position needs a `StackValue`, which no slice or array is: a parameter, a result, a `func(A) -> R`'s parts, a local's or an ascription's written type (`CheckValueType`), and a construction's or a load's value (checked in the body, `require_stack_value`); otherwise E2129 (`NotStackValue`), naming the part that makes it so (`Semantics::explain_non_stack_value`, only after a failed representation query) and suggesting `T: StackValue` for an abstract one. A field, a tuple element and a type argument need nothing, so `struct Header(len: u32, data: [u8; 16])`, `Box<heap, [u8]>` and `id::<[u8]>`'s argument are written freely (the last fails `id`'s own `T: StackValue`). Generic code states the bound (`func id<T: StackValue>(x: T) -> T`), and a trait whose functions take `Self` by value has `StackValue` as a supertrait (std's operator traits, `Memory`, `Global`, `Call`). See the note's "Values are `StackValue`s". Design and naming (*slice*, not *region*): `notes/slices-and-untyped-constants.md`
- Pointers always carry an ownership sigil — `*T`/`&T` (`*` exclusive, `&` shared); there is no `*mut T`. `.&` yields a shared reference (there is no `.&mut`). Each pointer belongs to a memory, always written (`heap::&[u8]`, or a memory parameter `Mem::*T`): there is no ambient or default memory, and an untagged pointer type is an error (E2038) however many memories are declared. The type formatter always prints that memory prefix — so a slice surfaces in diagnostics as `heap::&[u8]`, never `&[u8]`
- **`Pointer`** (std) is implemented by the compiler for every pointer type (`TraitImplLookup::Builtin`): `Memory` and `Pointee` read off the type, `Metadata` from the pointee (`Solver::pointer_metadata`): `()` for a value or an array, the length (`Memory::Size`) for `[T]`, `(len, inner)` for `[[T]]`; an abstract pointee is thin only when assumed a `StackValue` (nothing that is one holds a slice) or an `Array`, and otherwise its metadata is the rigid `<M::&T as Pointer>::Metadata`, so such a pointer is still a `StackValue`. Generic code that treats `M::*T` as an address bounds `T: StackValue` until `Sized` takes that over. Its supertrait equality (`Repr = <(Self::Memory::Size, Self::Metadata) as StackValue>::Repr`) is the representation, so std's `from_raw_parts`, `metadata` and `address` are `transmute`s. The metadata is on the pointer, not a Rust-style `Pointee`, because a count's type is the memory's; GATs are deferred (`notes/generic-associated-types.md`)
- **`Slice` and `Array`** (std) are implemented by the compiler for slices and arrays (source never implements them: an impl is written only for a nominal type, a struct, an enum or a primitive item, since its target is a path, and an alias naming a structural type is `InvalidImplTarget`): every `[T]` and `[T; N]` is a `Slice` (`Value` its element) and every `[T; N]` an `Array` (`LEN: {integer}` its length, which `resolve_constant` reads off the type). Their methods take the memory from the receiver (`func len<M: Memory>(self: M::&Self) -> M::Size`); writability is the receiver's ownership (`as_slice_mut(self: M::*Self)`), and a `self: M::&Self` method called on an exclusive pointer takes `receiver.*.&`. The solver answers them from the type's structure (`TraitImplLookup::Builtin`, `IntrinsicDefs::implements_structurally`), and member lookup adds them as candidates for `ImplTarget::Slice`/`Array` (`Semantics::trait_candidates`), so a method call on a pointer to a slice is an `AbstractMethodCall` of the declaration with the slice as `Self`. Lowering resolves one with a body (`first`, `last`, `as_slice`, `as_slice_mut`) to its default instantiated with that `Self`, and expands the two bodiless ones, `len` and `as_ref` (`IntrinsicDefs::supplies`), in place from the pointer's halves or the array's length. There is no conversion between arrays and slices but `as_slice`. Indexing anything but a place of a slice or an array, or a pointer to one, is E2125. A sized array is laid out inline (`Piece::Array` in `tir/layout.rs`: its elements' bytes, no values of its own), so a struct may hold one and an array may be an element; a slice field (an unsized tail) has no layout yet, and lowering reports it
- A string literal is the byte array of its length (`[u8; N]`), placed by its context as a shared byte slice (`Mem::&[u8]`) or a shared byte array (`Mem::&[u8; N]`); the node holds the unescaped contents as a symbol. There is no separate `string` type
- `local` / `local mut` declarations; `global` / `global mut` for module-level state. A global's value type must be one Wasm value (`Global::Value: StackValue where { Repr: StackScalar }`): `u32`, `Meters(u32)`, a pointer, `funcref` or `func(A) -> R` are, `()`, a slice or `Pair(u32, u32)` are not. `transmute<T, U>` (std, bodiless) reinterprets a value as another type with the same `StackValue::Repr`
- **`local <pattern> = expr` destructuring** — tuples, struct patterns written exactly like construction (`Point(a, b)`, `Point({ x, y: py, .. })`, with a full path), `_` (a drop, binds nothing), arbitrary nesting, and `..` to opt out of exhaustiveness. A struct pattern's positional list is one value of its fields, as a construction gives them (as in Standard ML): `P(t)` binds every field of `P(x: u8, y: u16)` as one `(u8, u16)`, `P(_)` matches any `P`, `P((a, b))` is `P(a, b)`, and a lone tuple field takes several (`W(a, b)` for `W(x: (u8, u16))`); `PatternKind::Struct` holds that one child. This is not sugar: there is no `t.0`, so destructuring is the only way to take a tuple apart. A tuple is laid out like a struct (sorted by alignment), but its values, like a struct's fields, stay in declaration order; only the byte offsets follow the layout.
- **Patterns:** what a term is follows from its own shape — a name binds, a literal compares with that value, a qualified path compares with that constant — and `const P` marks the one ambiguous case, a single-segment name that should compare with a constant (`const MAX`); it takes a path and nothing else, and before a path that is a constant already it is redundant (W1003, dropped by wx-fmt). The AST is one `Pattern` tree whose leaves are already resolved (`Binding`, `Constant`, `Literal`, `Or`, `Destructure`), so no later stage knows a mode; `..` is recorded as written and TIR judges it. A float or a string literal is read by the parser and refused by the checker (E2117). The alternatives of a `|` bind the same names, as in rustc: the same name in two alternatives is one local the arm's body reads, a name one alternative binds and another does not is E2118, the same name bound differently (`mut` or not) is E2119, and the same name of a different type is E2001. Plan: "Patterns" in `notes/tir-body-checking-plan.md`
- `const` — compile-time evaluated, inlined at every reference site, never emitted as a WASM global
- **Untyped constants** — `const X: {integer} = 4;` / `const U: {char} = 'u';`: the type is a literal kind, std's `pub type integer;`/`pub type char;` bound to `INTEGER_LITERAL`/`CHAR_LITERAL` and written in braces (`TypeExpression::Literal`; a bare `integer` is E2127, `{Point}` E2126, a literal kind anywhere but a free or trait constant's type E2128). The body stays untyped and is evaluated exactly (`eval_exact`, `i128`, `ConstValueState::Exact`); each use gives it a type as a literal's context does (`coerce_constant`) and whether its value is representable as that type is decided once values exist (`ExprObligation::Representable`; E2004, "constant `X` cannot be represented as `u8`", as a literal's is "literal `300` cannot be represented as `u8`"); as an array length it is a count. Never defaulted (E2002). A trait constant may be untyped (std's `Array::LEN`, read over a concrete type); an abstract one (a trait's over an unknown `Self`) is representable only as what a representability clause in scope implies (`T: Array where { const LEN: u8 }`, `Clause::Representable`, `tir/representable.rs`: range containment, an abstract type being every member of its typesets; else E2133, "constant `<T as Array>::LEN` cannot be represented as `u8`"), and a bound never states a constant's type, only this (on a typed constant it is E2134); impl constants, tuples of kinds and kinds inside an array constant are not done yet. Design: `notes/slices-and-untyped-constants.md`
- Functions, declared with `func` (renamed from `fn` to follow WAT), and `func(T) -> U` type expressions (first-class function references). A call passes arguments by position, `f(a, b)`, or by name, `f({ x: a, y })` (shorthand allowed); the two never mix (E1018). A parameter is written like a struct field, `binding: Type` or `Type` alone (binding `_`, `x` or `mut x`, always before a `:`; AST `enum Binding { Wildcard, Name }`, `binding: Option<Binding>`, `None` when left out): `func f(i32, _: u8, mut n: u32)`; a lone identifier is a type, the receiver is written with its type (`self: Self`; `self` alone is E1023), an unnamed parameter binds no local (`Body::params` maps parameters to locals), and `mut` needs a name (E1022). A call by name binds each argument to the parameter of its name; A call node holds one `args` value of the parameters its list fills (`()`, the lone argument, or a `Tuple` in written, evaluation, order with an `ElementOrder` saying which position each gives), as a struct construction holds its `fields`; a method call keeps its receiver beside it (`MethodCall`/`AbstractMethodCall`). The names are the selected function's, or for a trait impl's function its trait declaration's; a function with an unnamed parameter is called by position only (E2123); unknown, repeated and missing names are E2120/E2121/E2122. A struct construction is a call of its constructor, checked by the same code (`CallTarget`, read once per call from the function or the struct, and `build_arguments`; `CallTargetKind` says which, for diagnostics) with the same diagnostics, which name the target ("struct constructor `Point`") and point at its declaration. A method's receiver is `self` by name in `T::m({ self: x, .. })` and given by `x` in `x.m({ .. })`. An impl names each parameter as its trait does or leaves it unnamed (conformance, E2080): `_` binds no local and never changes the contract
- Structs, one form only: `struct Point(x: i32, y: i32);`, `struct Pair(i32, pub u8);`, `struct Unit();` — field names are optional per field, like `pub`. A struct is constructed by calling its name (`Point(1, 2)`, or `Point({ x: 1, y: 2 })` when every field is named), so the name is in the value namespace as well as the type one and a function cannot share it, but it is a value only when called: a constructor is not a first-class value (a bare `Point` is E2110; a function that calls it is the value to pass); the constructor is accessible only where every field is. Old brace forms (`struct P { .. }`, `P::{ .. }`) are reported (E1019/E1020) and parsed as the new ones
- `impl` blocks, `pub func` methods, `#[inline]` attribute
- Traits with default method bodies, associated types (`type Size: PointerSize`), associated consts, `impl Trait for Type`
- **A trait's function may require more of `Self`** by naming it first in its type parameters (`func as_slice<Self: Array where { .. }, M: Memory>`): the parser reads `Self` as an ordinary parameter name (as it does `self`), and the signature lowers it as clauses about the trait's `Self` in the function's env; it is not a parameter, so no argument is given for it (`x.as_slice::<heap>()`). The body assumes it and every use proves it with the rest of the function's env, reported at what gives `Self` (the receiver, or the path). A trait impl's function may write the same entry, about the impl's target (`<Wrap<T> as Container>::Item: Show`): a use proves it as written (its requirements), and the function assumes what it means, normalized once every signature exists (`NormalizeSelfEntry`, which completes the function's env: `T: Show`); a clause that is not about an abstract type is proved where it is written instead. Obligations name the item's frame and read its env when checked. Anywhere else `Self` is E2131. Design: `notes/env-normalization.md`. There is no `where` list: an inherent impl's method that needs more goes in another block. A binding block's constant entries are marked `const` (`const LEN: u8`, a representability clause; `const LEN = 4`, a value, still reported unsupported). Plan: `notes/tir-assumption-env-plan.md`
- **Operator overloading via trait dispatch** — std's operator traits (`Add`/`Sub`/`Mul`/`Div`/`Rem`/`Neg`, `BitAnd`/`BitOr`/`BitXor`/`Shl`/`Shr`/`BitNot`, `Not` for unary `!`, `PartialEq` for `==`/`!=`, `PartialOrd` for `<`/`<=`/`>`/`>=`) are recognized by name (`IntrinsicDefs`, `operators.rs`). An operator on a type with a primitive impl is a `PrimitiveBinary`/`PrimitiveUnary`; otherwise it is a call of the trait's method (`MethodCall`, or `AbstractMethodCall` for an abstract operand), and a missing impl is E2063. Primitive impls are `#[inline]` over intrinsics (ordering ones split signed/unsigned, `i32_lt`/`u32_lt`), so the output is still native `i32.add`/`i32.lt_s`. `PartialEq`/`PartialOrd` methods return `Bool`, and `PartialEq::ne` has a default body. Non-overloadable: `&&`/`||` and assignment.
- **Compound assignment** — `+= -= *= /= %=` and `&= |= ^= <<= >>=`, all sugar over the same resolved dispatch (`x = x.add(y)`), represented by a dedicated node family in TIR named on two axes: what defines the operation (`Primitive`/`Concrete`/`Abstract`) and where it writes (`Assign` for a local, `Store` for a place in linear memory), so `PrimitiveCompoundAssign` … `AbstractCompoundStore`. A plain operator is a `PrimitiveBinary`/`PrimitiveUnary`, or a call of its method: `Call` is a direct call of a known function by path (free functions, `Type::f(..)`, `Type::m(x, ..)`), `MethodCall` one with a receiver (`x.m(..)`, an operator's impl method, `Call::call` of a value), and `AbstractCall`/`AbstractMethodCall` the same of a trait's declaration, all holding the function's flat type arguments (an impl's, then its own; `[Self, own...]` for a trait's). Constants follow the same pair: `Const { constant, type_args }` for a known one (free, a variant, an impl's) and `AbstractConst` for a trait's declaration with `[Self]`
- Enums and `match` (lowered through `br_table`). The repr is written in parentheses like a struct's fields, `enum Ordering(i8) { .. }`; the old `enum Ordering: i8` is reported (E1024) and parsed as the new form, so `wx format` rewrites it. **An enum variant requires an explicit anchor value before auto-increment is legal** (E2071) — this closes a silent collision where `Ordering { Less, Equal = 0, Greater = 1 }` gave `Less` and `Equal` both 0.
- **Open enums** — an enum body may end in `..` (`enum Errno(u16) { Success = 0, Badf = 8, .. }`): the variants name some of the enum's values and every value of the repr is valid (a host's result, a `transmute` from the integer), where a closed enum takes its variants to be all of them. `ctor_set` gives an open enum `CtorSet::Open`: its variants and one more constructor for every other value of the repr, which only a wildcard covers, so a `match` needs a `_` or binding arm even when every variant has one (E2066, whose witnesses name the uncovered variants and then `_`); an open enum whose variants name every value of the repr has no rest and is a closed one in effect; nothing else changes (erased to its repr, no new lowering). The parser takes `..` as an entry like a variant (`ast::EnumEntry::{Variant, Rest}`, anywhere, any number of times) and judges nothing; the enum's signature warns about one that is not last (W2013) or a second one (W2014), and `check_discriminants` about one that is redundant because the variants already name every value (W2014). The prescan leaves `..` out of the variants' constant run, and `EnumDecl::open` is the span of the first. wx-fmt prints `..` in place and gives the last entry no comma when it is a `..`. Design: `notes/open-enums.md`
- Generics / monomorphization — `func f<T>(t: T) -> T`; a parameter is a type unless marked `const N: u32` (`ast::TypeParam::{Type, Const}`), and an argument is a type unless it is a literal or marked `const` (`f::<u32, 5, const SIZE>`; `const 5` is redundant, W1003, and wx-fmt drops it); const parameters and arguments are parsed but reported unsupported (E2114); lowering instantiates each generic function per argument list it is called with (`FunctionInstance`)
- `mod` declarations for multi-file compilation (the keyword is `mod`, not `module`). A module owns a directory per path segment: `a.wx` declaring `mod shared;` resolves `a/shared.wx`, exactly as Rust does, and `math.wx` / `math/mod.wx` are interchangeable for where `math`'s own children live.
- **Path keywords `package`, `self` and `super`** — real bindings in every scope's own table, created with the scope, so chaining (`super::super::x`) needs no special case.
- **`use` trees** — `UseTree::{Glob, Name, Path, Group}`, so nested groups and globs both work; named leaves are `UseItemDecl`s, resolved on demand (`imports.rs`).
- **Unqualified lookup does not climb to enclosing modules** (as in Rust): a name is looked up in the scope it is written in (its own declarations, its `use`s and globs), then in the std prelude, and nowhere else; a root item is `super::X` from a child module. Every later segment of a path is looked up only in the namespace the previous one named. **`std` is an implicit prelude**, the last tier, so a name std adds never shadows anything the user wrote or imported (`paths.rs`).
- Rust-style default visibility — an item without `pub` is visible to its declaring scope and every descendant, not to ancestors or unrelated modules. Checked for name lookup, qualified paths, `mod` and `use` re-exports, struct fields (E1076), and members reached through a type (`check_member_access`: an impl's member by its own `pub`, a trait's by the trait's).
- An inherent `impl` belongs in the package that defines the type (no `impl f32 { }` in user code); the old checker reported it (E2077, `ForeignImplTarget`), and the new one does not check it yet.
- `memory` declarations — `memory heap: u32;` (the type is the memory's `Size`) lowers to WASM linear memory; page limits via `#[memory_limits({ min_pages: .., max_pages: .. })]`
- **Package instances, `package "key" as alias;` / `pub package "key" as alias;`** — instantiate the package the manifest declares under `key` and binds it as `alias` in the scope the item is written in. Allowed in any module; private by default (visible to the declaring module and its descendants), and `pub` lets a consumer name the dependency through this package. An undeclared key is E2113, a missing `as` E1021. Each instance is its own instantiation site, recorded in `Namespaces::package_instances`, and its alias is a definition of its own (`DeclKind::PackageInstance(PackageInstanceIdx)`, with the alias as its declaration span). Resolution does not yet tell instances apart: a path through the alias continues into the package's one namespace (`Namespaces::entered_by`); a `Namespace::PackageInstance` per instance is the follow-up. An unknown key binds a poisoned alias (`BindingTarget::Error`), so a path through it ends silently instead of cascading. When codegen is revived, each instance must produce its own copy of the package's code. The stdlib is not instantiated this way; `std` stays implicit.
- `import "module" { func ... }` — WASM imports; `export { func, global }` — WASM exports (optionally renamed with `as "name"`). An export block must be unique per package, live at the binary root, and never appear in a library (E1072/E1073/E1074).
- Intrinsics are std's `pub package func` items. To the checker every package function is a `FunctionImplementation::Parameter`, std's included; lowering fulfils std's (the compiler is std's instantiator) through a map from std's package contract to their Wasm instructions by name (`std_intrinsics`, `Intrinsic::from_std_name`). No other package's package functions are fulfilled yet.
- Literals take their type from context, or from an ascription (`(5: u8)`). Integer literals are held as `u64`.
- There is no cast expression; `as` only names (`use x as y`, `package "k" as a`, export renames, `<T as Tr>`). Reinterpreting a value is std's `transmute` (same `StackValue::Repr`, checked by its bounds), and changing one is an instruction's (`i64_extend_i32_u`, `i32_reinterpret_f32`, …). Intrinsics are typed exactly as their Wasm instruction reads its operands (`i32_add(i32, i32)`, `u32_lt(u32, u32)`), so std's impls for other types `transmute` at the call: `transmute(i32_add(transmute(self), transmute(rhs)))`.
- `loop`, `break <value>`, `continue`, labelled blocks and loops: the label is written after the keyword, as it is after `break`/`continue` (`block :found { break :found x }`, `loop :outer { continue :outer }`). Only a `block` or a loop takes one (`Expression::Block`/`Loop` carry `label`); an `if` does not (E1025, read as `block :l { if .. }`), since a block around it gives the same exit
- **Type ascription** `(value: Type)`: an element of any parenthesized list (a tuple, a call's or construction's positional arguments: `(5: i32)`, `(a: u8, -1: i8)`, `f(x: u16, y)`) may carry a type, checked exactly as `local t: Type = value` would be, and converting nothing (`Expression::Ascription`; TIR adds no node for it). It covers the whole element (`(a + b: u64)`), and it is not an operator: `local x = 5: i32` is a parse error. Inside braces `:` still names (`f({ x: 1 })`). It replaced `as` for giving a value its type; `transmute` replaced it for reinterpreting one
- Block expressions (last expression without `;` is the value). A plain block is `block { ... }`: `{` alone never starts an expression, which keeps `f({ ... })` unambiguous; blocks owned by a construct (`if`/`else`, `loop`, match arms, function bodies) need no keyword. A bare `{` is reported (E1017) and parsed as a block. **A block-like expression (`if`, `match`, `loop`, `block`) is never an operand**: it fills a whole expression position (a statement, a `local`'s or an assignment's value, an argument, an arm, `return`/`break`'s value) and ends at its closing `}`, so `if c { .. } (a, b)` is two statements and an operator on either side needs parentheses, `(if c { f } else { g })(x)`, `x + (match ..)` (E1028, `parse_expression`). This is what lets wx-fmt drop the `;` after a multi-line block-like statement. Comparisons and assignments do not associate: `a < b < c` is E1007 and `a = b = c` (any of the assignment family) E1029, since an assignment's value is `()`

**Designed but not implemented:** the effect system (`does(...)` syntax — `notes/effect-system.md`, `notes/effect-tracking-plan.md`) and ownership/borrow checking (`notes/`, `devlog/2026-08-11-*`). Neither exists in the lexer, parser or stdlib. Don't describe them as features.

## Lowering and backend

1. **Lowering** (`tir/lower.rs`): starts from the exports and the globals, and lowers each `FunctionInstance` (a function with its type arguments) the first time something calls it, draining a worklist, so monomorphization is part of lowering. Layouts come from `tir/layout.rs` (fields placed in descending alignment, a stable sort; `#[fixed_order]` keeps declaration order; a tuple is always sorted), and a struct's values stay in declaration order, one MIR local per scalar, while TIR supplies the byte offsets each load and store is written at. Static data is the evaluator's value, placed in the memory its pointer type names (`tir/lower/statics.rs`). Wasm index ordering (imports first) is codegen's job.
2. **Inlining + dead-function removal** (`mir::inline::run`, called by `backend::emit`): callees first by Tarjan's strongly connected components (a call within a recursive component stays a call), each accepted call spliced in place over the arena, then a reachability walk from the exports and the start function drops what is dead and renumbers, so a `FunctionId` stays its index. `tir::lower` returns MIR as lowered. Plan and policy: `notes/mir-inlining.md`.
3. **Optimization** (`opt::optimize_reachable`, called by `backend::emit`): each reached function's body is rebuilt as a value/effect graph, each value placed (stored in a local, nested in its use, or fixed), and emitted back as a new MIR body; item IDs stay stable.
4. **Codegen** (`codegen::Builder::build`): each reached function is linearized from MIR into a `wasm::Function` (`codegen/linearize.rs`), then the module is encoded.

Compound assignment is not desugared anywhere: TIR keeps the `*CompoundAssign`/`*CompoundStore` nodes and lowering lowers them.

## Testing patterns

Tests live in `#[cfg(test)]` modules at the bottom of each source file.

**TIR (live):** a test lives in the module it tests (`typecheck.rs`, `eval.rs`, `layout.rs`, …), each with its own copy of the harness it needs; `tir/signatures.rs` holds the older signature tests. Signatures store types as written, so a test that asserts on what a projection *means* normalizes it first: `case.normalized_param("f", 0)`, `case.normalized(scope, ty)`, or `case.try_normalized_param(..)` for a type with no value (`Err(SolverError::Poisoned)`); `case.is_projection_param(..)` asserts the stored form. A `with_pending_signatures` test gets the context and a `SemanticsBuilder` (`|sema, builder|`) and drives queries through the latter (`builder.ensure_signature(sema, ..)`); one that looks impls up calls `builder.build(sema)` first. Every suite's `TestCase` owns what it was checked from, `tir::check`'s `Semantics` with the files and the interner (`case.strings`), and is built by a constructor: `TestCase::new("func f() {}")`; in the signatures suite also `TestCase::checked(..)` (asserts a clean parse and link) and `TestCase::from_graph(<CompilationUnit>, strings)`. Read state through `case.sema.<field>` (e.g. `case.sema.functions`, `case.sema.decls`, `case.sema.diagnostics`) and look items up with `case.resolve(..)`, which goes through real path resolution. The test source is a binary over the real embedded std (`signatures::tests::source_graph`, which the other TIR suites reuse), so it uses std's primitives, `Bool`, `Char` and traits as a user would. A test about what only std declares (intrinsic recognition, a deliberately minimal `Memory`/`StackValue`/`Call` world, arena positions) plays std itself with `TestCase::std(..)` / `TestCase::checked_std(..)` / `with_pending_std_signatures` (`std_source_graph`), and then declares its own primitives, `Bool`, `Char` and the `Call`/`Function` traits.

**Lowering and backend:** `tir/lower.rs`'s tests compile a source through `tir::check`, `tir::lower` and `backend::emit` and run the module under wasmtime; `backend_tests.rs` builds MIR by hand and runs it, to pin the MIR → Wasm contract without TIR.

**Legacy (not compiled):** `tir/tests.rs`, `tir/snapshots/`, `mir/tests.rs` and `codegen/tests.rs` belong to the old pipeline (`TestCase::new(..)` over a full `TIR`/`MIR`, with `insta` snapshots).

Test sources do **not** need `use std::*;` — the implicit prelude covers it.

`testing::DiagnosticView` is the shared vocabulary for diagnostic assertions: `assert_none`, `assert_no_errors`, `assert_error`, `assert_warning`, `assert_reported`, `assert_absent`, `assert_codes`, `assert_error_saying`. Prefer these over hand-rolled `matches!` or code-only checks — they render the offending source into the panic message and actually check severity, which a bare code comparison does not. `define_diagnostic_codes!` lives in `crate::diagnostics` and emits a `Code` trait impl, so one assertion accepts a code from any stage.

Adoption is uneven, so follow the suite you're in. `ast/tests.rs` and `vfs/tests.rs` are migrated: their `TestCase` exposes `diagnostics() -> DiagnosticView<'_>`, used as `case.diagnostics().assert_error(DiagnosticCode::…)`. The TIR suite's `TestCase::diagnostics()` also returns a `DiagnosticView`; the legacy `tir`/`mir` suites used a local free `assert_no_errors(&case)` helper. Write new assertions against `DiagnosticView` (construct one with `DiagnosticView::new(stage, diagnostics, files)`) rather than ad-hoc helpers.

Prefer assertions that state the claim over snapshots. The parser suite deliberately keeps only two snapshots (`top_level_items`, `use_tree_forms`) — genuinely structural cases — and expresses everything else directly; a `shape()` helper renders an expression as an S-expression (`a + b * c` → `(+ a (* b c))`) so precedence assertions name the tree they expect. Note that a snapshot of a *broken* parse still passes unless the test also asserts no diagnostics first.

Snapshot files live in `src/<stage>/snapshots/`. Never edit `.snap` files by hand. Only the two parser snapshots in `ast/snapshots/` belong to a compiled suite; the `.snap` files under `tir/`, `mir/`, `opt/` and `codegen/` (about 70) belong to the disconnected legacy suites (their `mod tests;` is commented out) and are not read by any test. If a parser change legitimately alters one of the two, regenerate with `cargo test -p wx-compiler` then `cargo insta accept`.

## Common pitfalls

- **Pre-interned `TypeIndex` ordering:** never insert in the middle of the pre-interned `vec![...]` literal in `TypeInterner::new()` (`tir/types.rs`) — every downstream type check silently gets wrong types. Add at the end only, and update the constants below it in the same file.
- **`ensure_signature` re-entrancy and early returns:** guarded by `SemanticsBuilder::query_state: HashMap<DeclId, QueryEntry>` (`QueryState::{Pending, InProgress, Resolved, CycleReported}`); re-entering an `InProgress` query is a cycle. It returns `SignatureStatus` — handle `Cycle`, or say why you don't with `let _ = ... // reason`. The cached-state check returns before a frame is pushed; after that, add no early `return`, so the `query_stack` frame is always popped by the unwind at the bottom.
- **A parse function's `Err` means it has already reported:** `SeparatedGroup`'s recovery skips tokens on an `Err` without reporting, so a parse function never fails silently. `parse_expression` reports when no expression starts; a caller to which one is optional (`break`'s value, `return`'s) checks `nud_lookup` on the next token first instead of reading `Err` as "absent".
- **Don't freeze or copy `Semantics`:** it is the one live owner of type state through body checking. A frozen registry, a second type interner, or `Arc`/`unsafe` to let the owner and its borrowed inputs coexist were all considered and rejected (`notes/tir-type-context.md`).
- **`Debug`/`Serialize` exist only in debug and test builds:** the derives are `#[cfg_attr(any(debug_assertions, test), derive(Debug, serde::Serialize))]`, so a release build has neither. std's `debug_assert_eq!`/`debug_assert_ne!` still type-check their operands in release (the expansion is `if cfg!(debug_assertions) { .. }`), so one on such a type needs `#[cfg(debug_assertions)]` on the statement, or the release build fails; `debug_assert!(a == b)` needs only `PartialEq`. Use std's macros; don't shadow them.
- **`transmute` back to a narrow integer is unchecked:** std's `u8`/`i8`/`u16`/`i16` operators run the `i32` instruction and `transmute` the result back, so `200 + 100` on `u8` is 300 under a `u8` type. Overflow checks are deliberately deferred (no build profiles yet); `Add` should trap rather than wrap when they come, and wrapping belongs to a separate `wrapping_add`.
- **Every package owns a root scope, including the root package.** A `Scope::Package` has no parent, so a walk up `.parent` ends inside the package it started in and never crosses into another. Don't add a global fallback: running out of parents *is* the package boundary. A package has no name of its own either; it is known by the `dependencies` key whoever declared it used.
- **`wx format` and the LSP formatting request must agree byte for byte.** Both go through `RendererConfig::from_manifest`. An already-formatted file must report *no* edits at all, or format-on-save dirties the buffer.
